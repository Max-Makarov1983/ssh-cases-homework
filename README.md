# Домашнее задание по теме «Работа с серверами и протокол удалённого управления SSH»

## Описание

В репозитории представлены результаты выполнения первых четырёх практических кейсов по теме SSH:

- **Кейс 1** — Установка и настройка SSH-сервера
- **Кейс 2** — Подключение к удалённому серверу
- **Кейс 3** — Копирование файлов с помощью SCP
- **Кейс 4** — Работа с ключами SSH

**Окружение:**
- Локальная машина: Ubuntu (хост VirtualBox)
- Удалённый сервер: виртуальная машина Ubuntu 22.04 LTS, IP `10.0.2.15`, пользователь `max`
- SSH-сервер: OpenSSH 8.9p1

## Кейс 1: Установка и настройка SSH-сервера

### Цель
Установить SSH-сервер, убедиться, что он запущен, проверить статус.

### Выполненные шаги

1. Обновление списка пакетов:
   ```bash
   sudo apt update
   ```

2. Установка SSH-сервера:
   ```bash
   sudo apt install openssh-server -y
   ```

3. Проверка статуса службы:
   ```bash
   sudo systemctl status ssh
   ```

4. Проверка прослушивания порта 22:
   ```bash
   sudo ss -tlnp | grep :22
   ```

### Результат

Служба `ssh.service` активна и запущена. Фрагмент вывода `systemctl status` сохранён в [`case1_ssh_server/ssh_status.txt`](case1_ssh_server/ssh_status.txt):


## Кейс 2: Подключение к удалённому серверу

### Цель
Подключиться к удалённому серверу по SSH с использованием имени пользователя и IP-адреса.

### Выполненные шаги

1. Определение IP-адреса сервера:
   ```bash
   ip a
   ```
   Используемый адрес: `10.0.2.15` (интерфейс `enp0s3`).

2. Проверка доступности порта SSH:
   ```bash
   nc -zv 10.0.2.15 22
   ```

3. Подключение к серверу:
   ```bash
   ssh max@10.0.2.15
   ```

4. Подтверждение ключа хоста при первом подключении (введено `yes`).

5. Ввод пароля пользователя `max`.

6. Проверка, что подключение выполнено к удалённой машине:
   ```bash
   hostname
   whoami
   ```

### Результат

Успешное подключение к серверу. Приглашение командной строки удалённого сервера, вывод `hostname` и `whoami` сохранены в [`case2_ssh_connection/ssh_connection_log.txt`](case2_ssh_connection/ssh_connection_log.txt).

**Вывод:** Подключение к удалённому серверу через SSH выполнено успешно ✅

## Кейс 3: Копирование файлов с помощью SCP

### Цель
Скопировать файл с локальной машины на удалённый сервер и обратно.

### Выполненные шаги

1. Создание тестового файла на локальной машине:
   ```bash
   echo "test file for scp" > test.txt
   ```

2. Копирование файла на удалённый сервер:
   ```bash
   scp test.txt max@10.0.2.15:/home/max/
   ```

3. Проверка наличия файла на сервере:
   ```bash
   ssh max@10.0.2.15 "ls -l /home/max/test.txt"
   ```

4. Удаление локальной копии и копирование файла обратно с сервера:
   ```bash
   rm test.txt
   scp max@10.0.2.15:/home/max/test.txt .
   ```

5. Проверка содержимого восстановленного файла:
   ```bash
   ls -l test.txt
   cat test.txt
   ```

### Результат

Файл `test.txt` успешно скопирован на удалённый сервер и обратно. Содержимое файла совпадает в обе стороны. Команды и результаты сохранены в [`case3_scp/scp_commands.md`](case3_scp/scp_commands.md), сам файл — [`case3_scp/test.txt`](case3_scp/test.txt).

**Вывод:** Копирование файлов с помощью SCP выполнено в обоих направлениях ✅

## Кейс 4: Работа с ключами SSH

### Цель
Сгенерировать пару ключей SSH, добавить публичный ключ на сервер, подключиться без ввода пароля.

### Выполненные шаги

1. Генерация пары ключей (без парольной фразы — для входа без запросов):
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N "" -q
   ```

2. Проверка созданных файлов:
   ```bash
   ls -l ~/.ssh/id_ed25519*
   ```

3. Копирование публичного ключа на сервер:
   ```bash
   ssh-copy-id max@10.0.2.15
   ```

4. Проверка, что ключ добавлен в `authorized_keys` на сервере:
   ```bash
   ssh max@10.0.2.15 "cat ~/.ssh/authorized_keys"
   ```

5. Проверка прав доступа на сервере:
   ```bash
   chmod 700 ~/.ssh
   chmod 600 ~/.ssh/authorized_keys
   chmod 700 ~
   ls -ld ~ ~/.ssh ~/.ssh/authorized_keys
   ```

6. Подключение к серверу без пароля:
   ```bash
   ssh max@10.0.2.15
   ```

7. Диагностика подключения (подтверждение входа по ключу):
   ```bash
   ssh -v max@10.0.2.15 2>&1 | grep -E "Offering|Server accepts|Authenticated"
   ```

### Результат

- Пара ключей `id_ed25519` / `id_ed25519.pub` сгенерирована.
- Публичный ключ добавлен в `~/.ssh/authorized_keys` на сервере.
- Вход выполнен **без запроса пароля**. В диагностическом выводе присутствует строка:
  ```
  Authenticated to 10.0.2.15 ([10.0.2.15]:22) using "publickey".
  ```

Файлы с результатами:
- [`case4_ssh_keys/ssh_keygen_output.txt`](case4_ssh_keys/ssh_keygen_output.txt)
- [`case4_ssh_keys/authorized_keys_check.txt`](case4_ssh_keys/authorized_keys_check.txt)
- [`case4_ssh_keys/ssh_key_login_log.txt`](case4_ssh_keys/ssh_key_login_log.txt)

**Вывод:** Пара ключей сгенерирована, публичный ключ добавлен на сервер, подключение по ключу без пароля работает ✅
